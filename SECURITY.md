# Безопасность персонального пространства

## Что действительно защищает запись

Публичная версия — статическая сборка. Имя, контакты и контент включены на этапе сборки и доступны посетителю только для чтения. Нет публичного POST-обработчика, базы пользовательских сообщений, почтовой формы или автоматического запуска CI при вводе кода. Настройки оформления локальны и не меняют профиль. Старый ключ локального предпросмотра удаляется.

Пять нажатий и код — **вход в интерфейс**, не доказательство принадлежности аккаунта. Короткий код нельзя считать сильным секретом. На статическом хостинге невозможно доверять клиентской проверке; посетитель всегда контролирует HTML и память своего браузера.

Поэтому реальное изменение проходит отдельное подтверждение **на github.com**. Workflow принимает ручной запуск только от владельца репозитория, для `main`, также проверяет инициатора повторного запуска. Сам сайт не получает пароль аккаунта GitHub, PAT или токен OAuth.

## Путь публикации

1. В панели создаётся черновик, а не публичное изменение. PIN через PBKDF2-SHA-256 даёт временный ключ HMAC. В репозитории находятся только соль, число итераций и проверочный хеш. Неэкспортируемый WebCrypto-ключ живёт в памяти до закрытия панели или тайм-аута 10 минут. Черновики и пакеты не пишутся в localStorage.
2. CH2 подписывает получателя, время, SHA-256 базовой версии **профиля и всего контента**, а также узкий набор правок. Нет произвольных путей JSON или файловой системы. Хеши новых фото входят в подписанные карточки. Срок — 30 минут (15 минут у совместимого CH1). Формат подтверждается из GitHub Actions владельцем для `main`.
3. До 8192 символов можно передать непосредственно. Для больших правок/фото панель формирует файл до 24 МиБ. Владелец прикладывает его к **неопубликованному** черновику релиза и передаёт workflow только имя. Чтение разрешено лишь из этого репозитория по проверенному имени, без URL из формы. При редиректе хранилища заголовок авторизации не пересылается. Загруженный черновик доступен людям с соответствующими правами в репозитории, не обычным посетителям. Скачанные пользователем файлы не удаляются завершением сеанса.
4. Исполнитель проверяет аккаунт, ветку, тип события, HMAC (`timingSafeEqual`), срок, адресата, базовую версию и точную схему полей. Фотографии проверяются по SHA-256, размеру, заголовкам, разрешению и фактическому декодированию JPEG с лимитом памяти. Не принимаются внешние URL вместо фото, неподписанные или недостающие вложения. Оригиналы изображений не публикуются: браузер перекодирует пиксели и отбрасывает служебные метаданные.
5. Только после проверок меняются `public/identity.json`, `public/content.json` и используемые `public/media/<sha256>.jpg`. Старые обложки удаляются из новой версии, но предыдущие коммиты остаются в истории Git. Текст рендерится React, метаданные экранируются. Недоверенные поля не подставляются в команду shell. Обычный fast-forward push без `--force`, затем Pages workflow с краткоживущим `GITHUB_TOKEN`. Режим `check_only` не пишет файлов, не коммитит и не публикует.

Ключ подписи хранится в GitHub Actions Secret `CHARON_OWNER_SIGNING_V1` и доступен лишь шагу проверки. Для начальной загрузки UI и публичного просмотра он не нужен. Официальные Actions закреплены по хешам коммитов; время и параллелизм задач ограничены, права объявлены на уровне jobs. Ветка не принимает автоматические изменения через issues, комментарии или pull_request_target.

## Политики браузера и ограничения данных

- Имя ограничено 32 символами, контактные ссылки — 384, email — 254. Управляющие символы не разрешаются. Принимаются HTTPS-ссылки и валидные адреса почты; для Telegram и GitHub проверяется домен. Неизвестные поля отклоняются. Одна и та же схема используется клиентом, сборщиком и серверной проверкой.
- Режим покупки требует активного проекта, цены и HTTPS-ссылки без встроенных логина и пароля. Режим запроса требует проверенного контакта в профиле. Сборка и подтверждение публикации проверяют это сочетание; старый CH1-пакет также не может убрать последний контакт, пока действует режим «По запросу». Проверка URL проверяет его формат, а не репутацию/принадлежность продавцу — владелец отвечает за ссылки и условия. Все опубликованные поля считаются открытыми, они не предназначены для токенов или персональных данных покупателей.
- Ссылки на оплату, документацию и внешние демо — обычная навигация по инициативе посетителя. Нет встраивания, прокси, серверной загрузки по этим URL, формы карт или обработки заказов. Генератор обложек использует текстовые SVG-узлы, локальный canvas и Blob; введённый текст не отправляется и не сохраняется.
- CSP сборки не допускает сторонних скриптов, inline-JS, eval, фреймов, загрузочных объектов, подмены base URL и отправки форм. Inline-стили нужны для геометрии интерфейса. В автономном HTML разрешён только конкретный SHA-256-хеш встроенного скрипта. Внешние ссылки имеют `noopener noreferrer` и действует `no-referrer`.
- Пять неверных кодов включают минутную паузу в текущей вкладке. Это **UX-ограничение**, не серверный rate limiter. Сами попытки входа не создают сетевого трафика.

## Доступность и спам

Статика, кэширование GitHub Pages, локальные шрифты и загрузка 3D по требованию уменьшают затраты на посещение. Нечего спамить на сервере сайта: он не принимает сообщения и не рассылает почту. Опубликованный контакт, разумеется, может быть прочитан ботом наравне с человеком.

Сетевой DDoS нельзя остановить клиентским JavaScript. За транспорт и CDN отвечает GitHub. Управляемые владельцем WAF, лимиты запросов и дополнительные HTTP-заголовки требуют соответствующего edge-хостинга или собственного домена с прокси. На стандартном `github.io` такие правила не настроены. Отсутствие известных предупреждений npm и зелёные тесты не доказывают абсолютную защищённость.

Проверки выпуска — локальные функциональные тесты, проверка схемы и прав, npm audit, обычная проверка опубликованных файлов по HTTPS. Атаки и нагрузочные прогоны против публичного сайта не выполняются.

## Смена кода

На доверенной машине с `gh`, авторизованным владельцем, в Bash:

```sh
read -rs -p 'Новый код владельца: ' owner_pin; printf '\n'
printf '%s' "$owner_pin" | node scripts/rotate-owner-code.mjs
unset owner_pin
git add src/config/owner-gate.json
git commit -m 'Ротация проверочного хеша владельца'
git push origin main
```

Ротация меняет секрет GitHub и публичный verifier; до публикации новой сборки старые пакеты перестают приниматься. Рекомендуется длинная уникальная фраза, двухфакторная защита GitHub и отзыв любого PAT, который передавался в чате. Доступный постороннему токен записи репозитория обходит защиту уровня приложения.
