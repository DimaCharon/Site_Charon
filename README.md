# Charon — авторская витрина цифровых продуктов

[Главная](https://dimacharon.github.io/Site_Charon/) · [Каталог](https://dimacharon.github.io/Site_Charon/products/) · [Студия обложек](https://dimacharon.github.io/Site_Charon/lab/)

Персональный сайт независимого разработчика. На главной — автор, одна основная кнопка **«Смотреть продукты»**, подборка работ и действующий пример. У каждого проекта есть отдельный адрес: кому он нужен, что уже доступно, стадия работы, демо или документация и способ покупки — если автор открыл продажу. Концепция не выдаётся за готовый сервис. Первая обложка — настоящий снимок работающей студии, а не макет.

## Запуск

Нужен **Node.js 20.19+** (для CI используется Node 22).

```sh
npm ci
npm run dev
```

```sh
npm run build        # проверка TypeScript + статическая сборка в dist/
npm run preview      # просмотр проверяемой сборки
npm run standalone   # самостоятельный out/Charon.html, работает без сети
```

## Что доступно посетителю

| Адрес                            | Что там можно сделать                                                                                                                                      |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                              | Познакомиться с автором, прокрутить подборку, открыть проект или быстрое досье. На знаке Charon — вращение, каркас и увеличенный просмотр.                 |
| `/products/`                     | Найти работу по названию, задаче или тегу и отфильтровать по стадии.                                                                                       |
| `/products/<id>/`                | Посмотреть аудиторию, результат, детали, материалы и блок «Доступ к продукту». Ссылка остаётся прежней при переименовании и перестановке карточек.         |
| `/contacts/`                     | Оставить короткий бриф: имя, задача, необязательный бренд, контакт и пример. Когда настроена доставка — получить подтверждение отправки в Telegram.        |
| `/references/`                   | Реальные экраны и демо, а не список концепций. «Хочу похожее» открывает форму с выбранным образцом.                                                        |
| `/lab/`                          | Собрать обложку: название, три материала, три рисунка и плотность линий. Экспорт PNG **1600 × 900** — в браузере, без аккаунта, сервера и передачи текста. |
| `/journal/` и `/journal/<kind>/` | Прочитать личную заметку по ссылке, посмотреть орбитальный атлас. Старые закладки `#interests` и `#world` со стартовой страницы перенаправляются сюда.     |
| `/guide/`, `/updates/`           | Узнать, что означают стадии, как работает доступ и что изменилось в выпусках.                                                                              |

Главная, каталог и страницы проектов/заметок — настоящие HTML-документы, а не только состояния React. У каждого — собственные заголовок, описание, canonical и карточка для соцсетей. При сборке создаются `sitemap.xml` и `404.html`. Каталог можно читать и обходить по ссылкам без JavaScript; интерактивному демо он нужен. У одиночного файла свой маршрут `#/products/…` без HTTP-сервера.

Поворот 3D-знака доступен перетаскиванием или стрелками на сфокусированной сцене, пробел ставит движение на паузу. Посетитель может переключать тёмную/светлую тему, движение и курсор. Системная настройка `prefers-reduced-motion` имеет приоритет.

## Контактная форма и существующий Telegram-бот

**[Подключить бота: пошаговая инструкция](relay/README.md).** Форма отправляет данные только с согласия посетителя. Не нужен новый бот, изменение webhook или публичный GitHub Issue. До подключения адреса доставки и в автономном HTML отправки нет: можно скачать черновик `.txt`. Поля не записываются в URL, cookies или localStorage; при ошибке остаются в открытой форме. Успех отображается только после подтверждения Bot API.

В галерее — проекты с опубликованным фото или демо, студийный знак и орбитальная карта. Карточки используют актуальные опубликованные тексты и материалы. Собственные снимки двух встроенных примеров лежат в `public/references/`. У каждого примера есть ссылка на действующий экран и переход `contacts/?ref=…`; старое `/#contacts` открывает новую страницу.

**Оформление:** в настройках доступны чёрная и белая темы. Фон страницы, стенд со знаком, формы и полоса браузера используют один выбор. При повторном открытии сохранённая тема применяется до запуска React. На телефоне каталог показывает крупные обложки, в шапке доступны снег, настройки и меню.

**Снег:** кнопка со снежинкой в шапке (в том числе на смартфоне) или Настройки пространства → «Снег на странице». По умолчанию выключен. Три слоя белых частиц падают с разной скоростью, изредка пролетает узорная снежинка. Эффект не перехватывает клики. На большом экране 84 частицы, на планшете 54, на телефоне 36. Выбор сохраняется только в браузере. При ограничении движения системой или вручную эффект отключён; при вводе брифа не мешает читать.

## Студия владельца

Внизу страницы **пять раз нажмите PERSONAL DIGITAL IDENTITY за 3,2 секунды** и введите свой код. Если вы переименовали подпись в редакторе, нажимайте на новую надпись — центральная кнопка подвала остаётся той же. Закрытие панели или десять минут бездействия завершают сеанс. Черновик живёт только в памяти вкладки: посетители не увидят его, пока вы не подтвердите публикацию.

- **Проекты.** Добавляйте и удаляйте карточки, меняйте их порядок стрелками у списка. Настройте название, краткое и полное описание, категорию, статус, пункты досье, теги и подпись на обложке. Справа — та же карточка, которую увидит посетитель: «Быстрый просмотр» открывает предпросмотр досье. На телефоне есть ссылка «Посмотреть карточку». Допустима пустая галерея; максимум 60 проектов.
- **Обложки.** Загрузите JPG, PNG или WebP до 16 МБ, выберите заполнение или показ целиком, положение кадра, описание для скринридера и один из четырёх материалов. Браузер уменьшит длинную сторону до 1440 px и перекодирует изображение в JPEG до 256 КиБ. Можно заменить снимок или вернуться к студийной графике. Внешний фотохостинг не нужен.
- **Тексты сайта.** Выберите один из 17 разделов или найдите фразу поиском. Доступны главный экран, навигация, «Обо мне» с шестью направлениями, проекты, витрина и покупка, студия обложек, журнал и гид, орбиты, интересы с вопросами и заметками, контакты, подвал, 3D-студия, настройки, модальные окна и поисковые метаданные. Направления, орбиты и заметки раскрываются под полями своего раздела. Текст сохраняется как текст, а не как HTML. Счётчики вычисляются автоматически; системные команды редактора не являются публичным контентом.
- **Профиль.** Меняйте имя и контактные адреса. Показываются только заполненные каналы. Они появляются под формой на странице контактов; токен бота сюда не вводится.

### Прямая кнопка на сайт продукта

В **Панели владельца → Проекты** выберите нужную карточку. В поле **«Сайт продукта»** под кратким описанием вставьте полный `https://`-адрес и подготовьте публикацию. Кнопка **«На сайт продукта»** появится в подборке на главной, в каталоге, быстром просмотре и на странице проекта. Она открывает указанный адрес в новой вкладке, без промежуточной страницы. Не нужно включать продажу, задавать цену или добавлять демо. Чтобы убрать кнопку, очистите поле и опубликуйте правку. У карточек без адреса кнопки нет.

### Как включить продажу продукта

Откройте **Проекты → нужная карточка → Демо, цена и продажа**. Заполните поля «Для кого продукт» и «Что получит посетитель». Выберите режим:

- **Только витрина** (по умолчанию): описание, пример и реальная стадия, без цены и кнопки покупки.
- **По запросу:** укажите условия и хотя бы один действующий канал во вкладке «Профиль». Первым выбирается Telegram, затем почта, соцсеть или GitHub. Для письма подставляется тема с названием проекта. Цену можно указать заранее.
- **Покупка на внешней странице:** статус **«Активный проект»**, полная цена с валютой/периодом и собственный **HTTPS-адрес** продавца обязательны. Добавьте условия, в том числе что получает покупатель. Витрина показывает цену, действие и домен перехода; оплату, доставку и возвраты обслуживает продавец, не этот сайт.

Демо независимо от продажи: встроенная студия, внешняя HTTPS-ссылка или без демо. Ссылка на документацию необязательна. Исходная поставка показывает семь проектов, не содержит выдуманных цен и не принимает платежей. Чтобы настройки стали публичными, подтвердите обычную публикацию ниже.

### Как опубликовать

1. Нажмите **Подготовить публикацию**. Панель проверит данные и покажет сводку. Если пакет небольшой и нет новых фото, **скопируйте пакет** и переходите к шагу 3.
2. **Для фотографий или большого объёма текста:** скачайте предложенный `charon-….json` без переименования. Под аккаунтом владельца в [Releases](https://github.com/DimaCharon/Site_Charon/releases) откройте новый или существующий **черновик релиза**, прикрепите файл и дождитесь загрузки. Для нового можно использовать имя файла без `.json` как название и тег. Нажмите **Save draft**, не **Publish release**. Скопируйте из панели **имя файла**, а не содержимое. Черновик релиза не становится публичным релизом.
3. В [Опубликовать правки Charon](https://github.com/DimaCharon/Site_Charon/actions/workflows/owner-profile.yml) нажмите **Run workflow**, оставьте `main`, вставьте пакет из шага 1 **или** имя файла из шага 2. Подтвердите запуск. Если хотите только проверить, включите `check_only`. При публикации дождитесь также успешного **Publish Charon**, затем обновите сайт. После успеха загруженный файл можно удалить из черновика релиза.

Пакет действителен 30 минут и привязан к исходной версии всего сайта. Если версия уже изменилась, обновите страницу и перенесите правки в свежий черновик. Если истёк только срок, не закрывая редактор, вернитесь к редактированию и заново подготовьте публикацию. Не помещайте сюда секреты. Страница не принимает GitHub PAT: право записи подтверждается **на github.com**, отдельно от PIN.

Вручную опубликованные данные находятся в `public/content.json`, `public/identity.json`, а проверенные фото — в `public/media/`. В сборку попадает только проверенная версия. Старые пакеты формата CH1 обслуживаются только для имени и контактов.

### Управление слайдами

Галерея проектов поддерживает нативные свайпы, горизонтальный трекпад и перетаскивание мышью. Увеличенные проектные досье, заметки об интересах, направления профиля и орбиты также переключаются горизонтальным жестом. На смартфоне карточки интересов образуют свайп-ленту. Вертикальная прокрутка, поворот 3D-объекта и обычные клики остаются независимыми; стрелки оставлены для клавиатуры и как доступная альтернатива.

### Оригинальный маскот

GLB в комплекте **нет**. Показан отдельный фирменный арт-объект — не замена персонажа другим маскотом. Добавьте оригинал в `public/models/charon.glb` и пересоберите сайт. Поддерживаются встроенные материалы и idle-анимация. [Требования к файлу](public/models/README.md).

## Технологии

React, TypeScript, Vite, Three.js и небольшие SVG-иконки Lucide. Страницы работают без серверного runtime; для реальных заявок нужен отдельный обработчик. Рендеринг знака, студийное освещение и шлифованный материал реализованы в Three.js, остальные этюды — параметрические SVG. Шрифты Manrope размещены локально, лицензия прилагается.

```text
src/
  components/   секции, 3D-viewport, модальные окна, настройки и эффекты
  config/       контент, типы, валидация профиля, локальные предпочтения
  owner/        скрытая панель, подпись и подготовка публикации
  hooks/        жесты мыши, сенсорного экрана и трекпада
  scene/        геометрия, материалы, свет и жизненный цикл WebGL
  styles/       базовая система, композиции секций, адаптивность
public/
  art/          оптимизированный WebP-рендер того же объекта
  fonts/        локальные вариативные шрифты: кириллица и латиница
  models/       слот необязательного GLB
  identity.json опубликованные имя и контакты
  content.json  публичные тексты, направления, проекты, орбиты и заметки
  media/        оптимизированные обложки по SHA-256
shared/         общая валидация, реестр текстовых полей и формат изменений
scripts/        проверка публикаций, статический рендер страниц и автономный HTML
tests/         браузерные сценарии и аудит доступности
```

## Производительность и доступность

- Текст и WebP-постер отображаются до инициализации WebGL. На компактном экране до 520 px и DPR до 2 браузер выбирает прозрачный постер 720 px (33 474 байта вместо 59 340); на экранах большей плотности и в увеличенной сцене остаётся оригинал 1080 px. Трёхмерный движок загружается отдельными чанками, только когда сцена приближается к экрану. На смартфонах и в режиме экономии трафика касание объекта или кнопки «Включить 3D» запускает полноценную сцену по запросу.
- Ограниченный DPR (1.45 на смартфонах, 1.7 на десктопах), цикл до 30 кадров/с. Рендер останавливается вне viewport, в скрытой вкладке и за модальным окном. В статическом режиме кадры рисуются по требованию.
- Студийное HDR-окружение заранее рассчитано и поставляется компактной таблицей отражений; браузер не пересчитывает свёртку освещения при каждом запуске. Нет внешних HDRI, шрифтов, аналитики, API-ключей или CDN. Без WebGL остаются настоящий рендер, контент и навигация.
- SVG-этюды загружаются по видимости, рассчитанная геометрия кэшируется. Изображения ниже первого экрана используют lazy loading.
- Нативные диалоги удерживают фокус, закрываются Escape и возвращают фокус на вызвавший элемент. Есть skip-link, подписи для кнопок и управление с клавиатуры.

## Проверки

```sh
npx playwright install --with-deps chromium
npm run build
npm run standalone
npm test
npm audit
```

Проверяются статические страницы без JS, ссылки из подпапки Pages, поиск и фильтры, настоящие байты PNG, офлайн-переходы и правила трёх режимов продажи. Проверки также охватывают совместимость CH1, правила подписи CH2, ограничения фотографий и частный транспорт через черновик релиза. Браузерные сценарии включают реальный WebGL и fallback, оба оформления, клавиатуру и жесты, read-only режим, панель на смартфоне, CRUD карточек и пустой архив. Сквозной тест загружает фотографию, редактирует разные разделы, подписывает пакет в браузере, применяет его в **изолированной копии репозитория**, пересобирает обе версии и открывает их как новый посетитель. Никакие тестовые проекты не публикуются. Для полноценного тестирования входа передайте собственный код через `CHARON_TEST_PIN` тестовому процессу. Без кода защищённые сценарии пропускаются.

**Безопасность, модель доступа, смена кода и ограничения защиты от DDoS** описаны в [SECURITY.md](SECURITY.md). Форма может только переслать заявку в настроенный чат: она не редактирует сайт, не пишет в репозиторий и не запускает GitHub Actions.

## Публикация

**GitHub Pages:** workflow `.github/workflows/pages.yml` собирает и публикует `dist/` при push в `main`. Источник публикации: Settings → Pages → GitHub Actions. Используется краткоживущая авторизация GitHub Actions, личный токен в проекте не нужен.

**Другой хостинг:** команда `npm ci && npm run build`, выходная папка `dist/`. Относительные пути поддерживают размещение в подпапке. Никаких rewrite-правил для маршрутизации не требуется. Для другого домена/базового пути задайте свой публичный адрес в `shared/routes.mjs` и в `public/robots.txt` (canonical, sitemap, ссылки для шаринга).

**Один файл:** `npm run standalone` создаёт `out/Charon.html` со встроенными скриптами, стилями, шрифтами, профилем, контентом и всеми используемыми изображениями. Откройте его в современном браузере.
