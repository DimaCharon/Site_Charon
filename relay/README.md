# Доставка заявок Charon в личный Telegram

Посетитель → форма `/contacts/` → ваш HTTPS-обработчик → `sendMessage` существующего бота → **ваш личный чат**. Сайт остаётся на GitHub Pages. Бот не читает чужие чаты. Для этой интеграции не нужно менять его команды, останавливать polling, читать `getUpdates` или удалять webhook.

### 1. Подготовьте получателя

Откройте личный чат со **своим существующим ботом**, нажмите Start или отправьте `/start`. Бот не может первым написать человеку, который его не запускал. В адрес получателя нужен ваш **числовой** `message.chat.id` из личной переписки — не имя бота, не `@username`, не номер телефона. Если бот уже обрабатывает команды, получите ID из события `/start` через его существующую админку/код. Не переадресовывайте сообщения или секреты неизвестным ботам.

### 2. Разместите обработчик у себя

**Через браузер** (после публикации этого кода в репозиторий): в Cloudflare Workers & Pages подключите свой репозиторий и ветку `main`. Имя Worker — `charon-contact`; корневая папка сборки — `relay`, build command пустой, deploy command — `npx wrangler@4 deploy`. Лимитеры задаёт `wrangler.toml`. В **Worker → Settings → Variables and Secrets** добавьте два значения с типом **Secret** (именно настройки работающего Worker, не переменные сборки):

| Имя                  | Значение                                   |
| -------------------- | ------------------------------------------ |
| `TELEGRAM_BOT_TOKEN` | Токен существующего бота из BotFather      |
| `TELEGRAM_CHAT_ID`   | Ваш положительный числовой ID личного чата |

Сохраните/разверните новую версию. Для сайта `dimacharon.github.io` Origin уже настроен. Если у аккаунта заняты namespace ID `41071`/`41072` или имя Worker, выберите свободные значения в `wrangler.toml` до развёртывания. Проверьте лимиты и условия своего аккаунта Cloudflare.

**Либо с компьютера** (Node.js 22.12+ и ваш аккаунт Cloudflare). Откройте терминал в `relay/` этого репозитория или в **распакованной папке готового комплекта обработчика** и выполните:

```sh
npx wrangler@4 login
npx wrangler@4 deploy
npx wrangler@4 secret put TELEGRAM_BOT_TOKEN
npx wrangler@4 secret put TELEGRAM_CHAT_ID
```

Введите значения в скрытые запросы терминала, не в команду, исходники или чат с помощником. Только Worker получает токен. Команда `deploy` выведет публичный адрес вашего Worker.

### 3. Подключите адрес к форме

К адресу Worker добавьте **`/contact`**. Только этот публичный URL впишите в `src/config/contact-delivery.json` сайта (или передайте его помощнику). Пример **формата**, не готовый URL:

```json
{ "endpoint": "https://charon-contact.YOUR-SUBDOMAIN.workers.dev/contact" }
```

Замените `YOUR-SUBDOMAIN` на настоящий адрес в нижнем регистре. Сделайте commit в `main` и дождитесь **Publish Charon**. Не указывайте адрес Bot API, токен, ID чата или параметры `?key=…`. Пустой `endpoint` отключает доставку. Доступ к боту не нужен сборщику сайта. Не выкладывайте `.dev.vars`, персональные сообщения, ключи или логи бота.

### 4. Проверьте получение

На **опубликованном сайте** откройте «Референсы» → «Хочу похожее», заполните короткую тестовую заявку своим контактом, отметьте согласие и отправьте. Дождитесь **«Заявка отправлена»** и **проверьте сообщение в Telegram**: в нём имя, бренд (если указан), задача, контакт для ответа и выбранный пример. Кнопка «Отправить» активна только в сетевой сборке с адресом; локальный HTML никогда не отправляет личные данные. Если бот заблокирован, чат неверен или сеть не ответила, сайт не объявляет успех. Не повторяйте заявку сразу после тайм-аута: первое сообщение могло дойти.

Для другого домена смените `SITE_ORIGIN` в `wrangler.toml` на точный HTTPS-origin (без пути и завершающего слеша), затем заново разверните Worker. Не ставьте `*`. Не проверяйте работоспособность вводом реальных данных клиентов.
